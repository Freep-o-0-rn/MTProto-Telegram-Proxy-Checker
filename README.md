# TelegramProxyChecker

Android-приложение для поиска и проверки MTProto-прокси для Telegram.

Приложение загружает список MTProto-прокси, проверяет доступность сервера по TCP, затем выполняет реальную проверку через Telegram-клиентский слой с использованием TDLib. Это позволяет отличать просто открытый порт от прокси, который действительно может работать с Telegram.

[⬇️ Скачать последнюю версию APK](https://github.com/Freep-o-0-rn/TelegramProxyChecker/releases)

## Возможности

- загрузка и объединение нескольких автоматически обновляемых источников MTProto-прокси;
- TCP-проверка `server:port`;
- реальная Telegram-проверка через TDLib `TestProxy`;
- отображение статусов `TCP OK / FAIL` и `Telegram OK / FAIL`;
- сортировка рабочих прокси выше нерабочих;
- кэширование результатов проверки;
- повторное использование свежих результатов до 30 минут;
- избранные прокси;
- точечная повторная проверка одного прокси;
- фильтр рабочих прокси;
- фильтр избранных прокси;
- переход в Telegram для подключения выбранного прокси.

## Редизайн главного экрана (гибрид Dashboard + Telegram)

- Тёмный компактный Dashboard показывает Telegram OK, всего прокси и TCP OK; при прокрутке статистика уходит с экрана.
- **Счётчики Dashboard — кнопки фильтра:** «Telegram OK» показывает строго `telegramOk == true`, «Всего» показывает весь кэш, «TCP OK» показывает все прокси с `tcpOk == true` (включая не прошедшие Telegram-проверку). Для «TCP OK» сортировка по TCP ping, для остальных — по Telegram ping. Активный счётчик выделен, а при прокрутке TCP-фильтр показывается в закреплённой панели с кнопкой сброса. Поиск, избранное, раскрытие карточек и фоновая проверка не меняются.
- Прогресс, управление паузой/возобновлением/остановкой и вкладки закреплены вверху списка. Команды используют тот же `ProxyScanService`, что и уведомление Android.
- По умолчанию показываются только **Telegram OK**. Вкладки «Все» и «Избранное» доступны всегда.
- Сортировка в интерфейсе — по возрастанию **Telegram ping**, подтверждённые рабочие прокси выше остальных. Это не изменяет порядок сканирования или кэш.
- Поиск по адресу сервера/IP и порту. При просмотре середины списка результаты внутри строк обновляются, а порядок фиксируется до возвращения наверх.
- Нажатие на строку раскрывает TCP, Telegram, время проверки, ошибку TDLib и скрытый по умолчанию секрет.
- Быстрое подключение — **явная кнопка «Подключиться»** в каждой строке, а также расширенная кнопка внутри раскрытой карточки. У нерабочих прокси кнопка визуально второстепенная, но активная.
- Кнопка ↻ и меню «Проверка» повторно проверяют **ранее TCP OK** прокси через TDLib без ожидания 30 минут. Это не полноценный поиск новых серверов и не замена полному сканированию.
- Меню ⋮: «Проверка», «Полная проверка», «Скопировать диагностику». Настройки открываются только через ⚙.
- «Полная проверка» заново проверяет **все** MTProto-прокси; автоматическое обновление по истечении TTL оставлено отдельно.
- Метка активного процесса — «Сканирование» (без «в фоне»). Область нажатия для раскрытия строки скруглена.

## Источники в настройках (несколько MTProto)

- Сверху расположены четыре независимых MTProto-источника: **SoliSpirit**, **tgmtproxy**, **shablin**, **dubblebyte**. Все четыре **включены по умолчанию**; каждый можно отключить отдельно. Настройка SoliSpirit переносится из прежней версии.
- Внизу — **hookzof SOCKS5**, **выключен по умолчанию**. Если он был включён вручную раньше, этот выбор сохраняется.
- Прямые адреса файлов:
  - `https://raw.githubusercontent.com/SoliSpirit/mtproto/master/all_proxies.txt`
  - `https://raw.githubusercontent.com/tgmtproxy/mtproxy/main/proxies.txt`
  - `https://raw.githubusercontent.com/shablin/mtproto-proxy/main/data/valid_proxy.txt`
  - `https://raw.githubusercontent.com/dubblebyte/free-mtproto-proxies/main/all_proxies.txt`
  - `https://raw.githubusercontent.com/hookzof/socks5_list/master/proxy.txt`
- Парсер MTProto принимает `https://t.me/proxy` и `tg://proxy` с параметрами `server`, `port`, `secret`; комментарии/неверные строки игнорируются, суффикс после `|` отбрасывается.
- SQLite хранит состав каждого списка независимо; в общей очереди прокси с одинаковыми `protocol/server/port/secret` проверяются **один раз**. Отключение одного источника не скрывает прокси из другого включённого источника.
- Показатель **«Уникальных адресов в выбранных источниках»** рассчитывается по SQLite без повторов. На каждой карточке отображаются число адресов и время последнего успешного обновления.
- При старте фонового сканирования обновляются только включённые устаревшие источники (интервал 30 минут), последние успешные снимки остаются при сетевых ошибках. Настройки можно обновить вручную.
- Ссылка подключения подбирается по типу протокола: `tg://proxy` для MTProto, `tg://socks` для SOCKS5 (включая необязательные логин/пароль).
- Результат **Telegram OK** по-прежнему требует успешного ответа TDLib. Сам факт присутствия адреса в GitHub не означает его доступность.

## Очистка локальной базы прокси

- В самом низу настроек — **«Хранилище прокси» → «Очистить базу прокси»**, с подтверждением удаления.
- Удаляются строки SQLite из `checked_proxies`, `source_entries`, `source_inventory` и `source_cursors`: результаты TCP/Telegram, сохранённые адреса, избранное и позиции обхода. Старый JSON в `SharedPreferences/proxy_cache` также инвалидируется, чтобы он не восстановил прокси.
- Очистка выполняется транзакционно; `VACUUM` после удаления возвращает свободные страницы базе SQLite, когда это доступно. Статус удаления и сжатия показывается в настройках.
- Список в памяти `ScanSession` и журнал уже записанных результатов сбрасываются вместе с базой; отложенный `saveCache` не должен повторно вернуть старые адреса.
- Во время сканирования, точечной проверки, импорта источников или уже начатой очистки кнопка недоступна.
- **Настройки приложения и выбранные источники сохраняются**. Списки автоматически загружаются заново при следующем сканировании (либо вручную через «Обновить» в настройках). Избранное при полной очистке не сохраняется.

## Регулировка скорости проверок

- В настройках доступен ручной регулятор **1–30 параллельных работников** (ранее всегда 6) и режим **«Автоматически»**. По умолчанию установлено 5.
- Автоматический режим консервативно выбирает число работников по числу процессоров, классу памяти приложения и признаку low-RAM. Это ориентир нагрузки устройства, а не гарантия скорости сети.
- Ручной режим допускает значения до 30; максимальное число работников **в общем** между массовой и одиночными проверками.
- **TDLib ограничен отдельно шестью одновременными клиентами** (или меньшим количеством, если работников меньше). Каждая проверка TDLib продолжает тестировать дата-центры прежним способом. Увеличение количества предварительных TCP/SOCKS5 проверок не повышает число одновременно тестируемых через TDLib прокси.
- Пауза, остановка, фоновые уведомления, очередь, критерий Telegram OK и лимит количества проверяемых адресов сохранены. Настройки скорости применяются при начале **следующего** сканирования и сохраняются между запусками.
- Высокая параллельность может влиять на нагрузку и фактическое время ответа сети; окончательно сравнить точность и производительность режимов 5/15/30 следует на телефоне через одинаковые выборки и диагностические отчёты.

## Реальная SOCKS5-проверка (этап 4)

- Источник `hookzof/socks5_list` действительно проверяется после включения SOCKS5 в настройках. Контрольного фиксированного числа серверов нет — каталог загружается из GitHub, а лимит текущего прохода выбирает пользователь (число от 1 до суммы включённых списков или режим «Все»).
- Отдельный протокольный SOCKS5 handshake (RFC 1928/1929) отвергает открытые TCP-порты без SOCKS5. После успешного согласования выполняется **TDLib TestProxy** с типом `ProxyTypeSocks5`; Telegram OK выдаётся только по `TdApi.Ok`, как и для MTProto.
- Ссылки подключения формируются протокольно: `tg://socks?server=…&port=…` или `tg://proxy?server=…&port=…&secret=…`; HTTPS fallback повторяет корректный тип.
- SQLite хранит результаты обоих типов. Следующая SOCKS5-партия выбирается из источника с приоритетом непроверенных, затем давно проверенных по `checked_at`. При прерывании прогресс сохраняется через SQLite, не зависит от номера строки и устойчив к изменению GitHub-списка.
- Существующие действия «Проверка» (ранее TCP OK) и «Полная проверка» сохранены. Общая очередь ограничена указанным лимитом; число работников теперь задаётся отдельно (см. раздел о скорости).
- Из-за размера публичного SOCKS5-списка по умолчанию лимит **500 адресов за запуск**, а не авто-проверка всех десятков тысяч. Это *значение лимита*, не количество адресов репозитория, и его можно менять или выбрать «Все».
- Проверки и результаты TDLib и SOCKS5 handshake следует проверить на реальном Android; успешные JVM-тесты не означают, что в конкретной сети найдены живые прокси.

## Подготовка двух источников и SQLite (этапы 1–3)

- Общая модель `MtProxy` сохраняет старые MTProto поля/ключи и добавляет `protocol`, `sourceId` и необязательные `username/password` для SOCKS5. Сам SOCKS5 пока **не проверяется** и не подключается в Telegram.
- Результаты MTProto теперь сохраняются в `proxy_checker.sqlite` (`checked_proxies`). Предыдущий кэш `SharedPreferences/proxy_cache/proxies_json` импортируется **в транзакции**, включая TCP/Telegram статусы, ping, время, избранное. Старый JSON удаляется только после успешного коммита; при невозможности разобрать JSON он сохраняется.
- Таблицы `source_entries`, `source_inventory`, `source_cursors` зарезервированы для дальнейшей общей очереди: записи каждого источника, количество актуальных уникальных адресов, последний обработанный ключ и номер цикла. Курсор ещё не подключён к действующему сканированию.
- При открытии настроек приложение скачивает **оба** исходных списка и показывает фактическое количество валидных уникальных прокси; никаких числовых констант количества в приложении нет. Списки сохраняются в SQLite отдельно. При ошибке загрузки остаётся последняя сохранённая версия, отображается предупреждение.
- SOCKS5 из `hookzof/socks5_list/proxy.txt` парсится как `IP:порт`, без авторизации. В настройках можно сохранить выбор этого источника, но пока это **только подготовка**. Очередь `ProxyRepository` и TDLib `ProxyTypeMtproto` остаются без SOCKS5.
- Сканирование MTProto, кнопки «Проверка»/«Полная проверка», фоновые уведомления и ограничение **6 параллельных проверок** на этом этапе не меняются. Отдельная SOCKS5-проверка и настраиваемая очередь/лимит/параллельность — следующие этапы.

## Как работает проверка

Приложение выполняет две проверки:

1. **TCP-проверка**  
   Проверяется, открывается ли соединение с `server:port`.

2. **Telegram-проверка**  
   Проверяется MTProto-прокси через TDLib. Такой тест показывает, может ли прокси реально использоваться Telegram, а не просто имеет открытый порт.

Возможные результаты:

```text
TCP: OK
Telegram: OK
```

Прокси доступен и прошёл Telegram-проверку.

```text
TCP: OK
Telegram: FAIL
```

Порт открыт, но как Telegram-прокси сервер не работает.

```text
TCP: FAIL
Telegram: FAIL
```

Сервер недоступен.

## Фоновое сканирование

- Общий проход выполняется в foreground service типа `dataSync` и продолжается при сворачивании или закрытии окна приложения.
- Уведомление показывает прогресс, паузу/возобновление и остановку (системный шаблон Android, без подмены под медиаплеер).
- Счётчик проверки в интерфейсе и уведомлении берётся из **одного** состояния сканирования; исчезло пропускание уведомлений внутри прежних 500 мс. Фактическое время отрисовки системной шторки может зависеть от Android.
- Пауза не прерывает уже запущенные проверки, но приостанавливает выдачу новых заданий; возобновление продолжает текущую очередь.
- Остановка отменяет проверку, сохраняет полученные результаты и удаляет уведомление.
- Результаты периодически сохраняются и отображаются при повторном открытии приложения.
- На Android 13+ для отображения в шторке требуется разрешение на уведомления. Android 15+ ограничивает тип `dataSync` шестью часами фоновой работы за сутки.
- Принудительная остановка всего приложения средствами Android и убийство процесса не гарантируют завершение сохранения последних результатов.

## Скорость сканирования

- Одновременно проверяются до **6 прокси**; очередь использует фиксированное число корутин.
- DC1 Telegram проверяется сразу. Если результат ещё не получен, остальные DC запускаются с интервалом 200 мс. Первый успешный ответ завершает проверку прокси; ошибка ставится только после неудачи всех пяти DC.
- Тайм-аут TCP остаётся 5 секунд, TDLib `TestProxy` — 5 секунд на DC, ожидание callback — 7 секунд. Ускорение не основано на сокращении времени для медленных серверов.
- Каждая проверка владеет своим TDLib-клиентом. При завершении или отмене отправляется `Close`, чтобы остановить оставшиеся нативные запросы.
- Первый результат показывается сразу после получения; следующие обновления списка объединяются примерно раз в 200 мс, окончательный результат — всегда. Фильтр рабочих прокси доступен во время сканирования.
- Чтение и сериализация кэша выполняются вне UI-потока. Изменения избранного во время проверки сохраняются.
- Точечная перепроверка временно недоступна во время общего сканирования; общее сканирование не запускается до завершения точечных проверок.

Детерминированный тест `ScanPerformanceTest` сравнивает старый и новый порядок выполнения на **60 одинаковых моделируемых прокси** с TCP-задержкой 50 мс:

| Модель ответов Telegram | Раньше | После оптимизации |
| --- | ---: | ---: |
| Первый DC отвечает успешно за 100 мс | 3,0 с | 1,5 с |
| Все пять DC завершаются тайм-аутом через 5 с | 501,0 с | 58,5 с |
| Только DC5 отвечает за 100 мс, остальные — тайм-аут | 403,0 с | 9,5 с |

Это **виртуальное время теста планировщика**, а не замер на телефоне. Оно не учитывает нагрузку нативной TDLib, DNS, потери пакетов и ограничения сети. Реальное ускорение нужно измерять на устройстве. Результат по признаку `Telegram OK/FAIL` в тесте совпадает со старым алгоритмом.

## Диагностика Telegram OK / FAIL

- **Telegram OK** фиксируется исключительно при успешном ответе TDLib `TestProxy`. Открытый TCP-порт сам по себе не означает рабочий прокси.
- Ответы TDLib `Error` сохраняются вместе с числовым кодом и сообщением. Сообщения доступны в карточках прокси.
- В блоке статистики показываются наиболее частые причины отказа. Кнопка «Скопировать диагностику» формирует отчёт без MTProto-secret и ссылок подключения.
- Секреты передаются в TDLib в исходном виде: список содержит разные допустимые представления, которые нельзя преобразовывать без проверки на устройстве.
- При отсутствии хотя бы одного `Telegram OK` следует изучить ошибки TDLib и отдельно проверить конкретный адрес непосредственно в Telegram. Без этого нельзя доказать неисправность теста или работоспособность серверов.
- При обычном обновлении проверяются **все** устаревшие прокси, включая ранее неработающие; ограничение в 20 удалено. Записи с проверкой моложе 30 минут остаются в кэше. Неработающие серверы проверяются от самых давно проверенных к более новым.
- Кнопка «Полная Telegram-проверка» запускает `TestProxy` для **каждого** прокси независимо от возраста кэша и даже при отрицательном предварительном TCP-тесте. Это медленнее, но позволяет избежать ложных отрицательных результатов из-за различий сетевых путей/DNS. Точечная проверка также выполняет этот углублённый тест.
- При открытии приложения свежий кэш отображается без автоматического повторного запуска проверки. Ручная кнопка по-прежнему обновляет источник и проверяет только кандидатов, которым требуется проверка.

## Кэширование

Кэш нужен для быстрого запуска приложения и уменьшения количества повторных проверок.

Логика работы:

1. При запуске приложение сразу показывает сохранённый список из кэша.
2. Прокси, проверенные менее 30 минут назад, повторно не проверяются.
3. Сначала перепроверяются ранее рабочие `Telegram OK` прокси.
4. Затем проверяются новые прокси.
5. После этого ограниченно перепроверяются старые `Telegram FAIL` прокси.
6. Избранные прокси сохраняются между запусками.

## Избранное

Прокси можно отметить звездой. Избранные прокси:

- сохраняются в кэше;
- отображаются выше обычных прокси;
- могут быть отфильтрованы отдельной кнопкой.

## Точечная проверка

У каждого прокси есть кнопка повторной проверки. Она запускает проверку только выбранного сервера, не перепроверяя весь список.

Во время проверки кнопка показывает вращающиеся стрелки.

## Технологии

- Kotlin;
- Android;
- Jetpack Compose;
- Coroutines;
- TDLib;
- SharedPreferences для локального кэша.

## Сборка проекта

Открыть проект в Android Studio и выполнить сборку:

```powershell
.\gradlew clean :app:assembleDebug
```

Для запуска на телефоне нужен включённый режим разработчика и отладка по USB.

## Важно

Проект не является официальным продуктом Telegram. Приложение не владеет прокси-серверами и не гарантирует их стабильность. MTProto-прокси могут быстро переставать работать, поэтому результаты проверки всегда имеют ограниченный срок актуальности.
